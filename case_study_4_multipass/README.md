# CS4 — Multi-pass HCP Mg texture evolution (ZX31, Mg-3Zn-0.3Ca)

Same harness as CS2 (goal-driven single ReAct agent; agent loop + system prompt
unchanged). Only the **tools, data, and query** differ. This folder is the ZX31
(Mg-3Zn-0.3Ca) case at 1728 grains used in the paper.

## What the agent does
From the natural-language goal (`config.DEFAULT_QUERY`) it orchestrates a **chained
five-pass** simulation of hot rolling, then two comparisons:
1. **After pass 1** — validate the single-pass mechanical response
   (plane-strain flow stress `sigma_yy - sigma_zz` vs true strain) against the
   reference simulation (RMSE / MAPE).
2. **After pass 5** — analyse the (0001) basal-texture evolution (peak intensity vs
   pass) and compare the final texture to the reference 5-pass simulation and to the
   experiment.

The chaining is the point: each pass's deformed orientations become the next pass's
initial texture. `run_pass(N)` carries that state forward automatically, so the
agent orchestrates the loop by calling `run_pass` for N = 1..5 in order.

## Tools (`tools/react_tools.py`)
| Tool | Role |
|------|------|
| `run_pass(pass_number)` | run one rate-dependent pass; pass N>1 auto-starts from pass N-1's deformed texture |
| `compare_stress_strain` | after pass 1: `sigma_yy - sigma_zz` vs reference sim (RMSE/MAPE) |
| `analyze_texture_evolution` | (0001) max intensity per completed pass (MTEX) |
| `compare_final_texture` | pass-5 texture vs reference sim (+ experiment); builds comparison figure |

## Key requirements (why CS4 is non-trivial)
- **Rate-DEPENDENT model** (`../../main_ratedep`). The default `../../main` is
  rate-independent and gives physically wrong twinning/stress for these HCP alloys.
- **Substepping**: >= 75 Taylor substeps for stable HCP integration (100 for ZX31).
  Set in `config.SUBSTEPS`.
- **Cubic mesh** (this build segfaults on non-cubic meshes). Grain count = `SUBDIV^3`
  (`SUBDIV = 12` -> 1728 grains).
- prm quirk: `Number of User Material Constants 1` is forced to 12 (the deck lists 12
  values but declares 13).

## Layout
```
config.py                      alloy params, reference paths, DEFAULT_QUERY
run_pipeline.py                entry point
prm.prm                        Table-1 350C deck for ZX31
orientations_initial.txt       random as-cast start (pass-1 input)
grainID.txt                    cubic voxel->grain map
slip*/twin*/LatentHardening*   geometry (NoPyrA slip set + extension twins)
reference/                     authors' 1-pass stress, 5-pass texture, experiment PNG
tools/                         sim_tools, stress_tools, texture_tools, matlab_runner, react_tools
matlab/pole_figure.m           (0001) pole figure + max intensity (MTEX)
agents/react_agent.py          ReAct loop (harness core, as CS2)
```

Heavy per-pass run artifacts (`QuadOut_pass*.csv`, per-pass working directories,
generated pole-figure PNGs) are regenerated by running and are omitted here;
`texture_results.txt` is retained as a small example summary.

## Result (reproduces the reference)
The five-pass chain reproduces the reference simulation closely: the pass-1
plane-strain flow stress is 138.5 MPa vs 138.8 MPa for the reference, and the (0001)
peak intensity rises from 2.10 MRD (pass 1) to 5.66 MRD (pass 5), against the
reference 1.94 -> 5.46 MRD. The texture stays weak and splits toward the rolling
direction, the signature of a Ca-containing alloy.

## To run
```bash
export OPENAI_API_KEY='sk-...'
export MTEX_ROOT="/path/to/mtex-6.2.beta.3"   # folder containing startup_mtex.m
python3 run_pipeline.py                        # uses config.DEFAULT_QUERY
```
Set the Windows MATLAB path in `tools/matlab_runner.py` if it differs. Runtime is
dominated by the rate-dependent solver (roughly one hour per pass at 1728 grains).
See the repository root `README.md` for using a non-OpenAI provider.
